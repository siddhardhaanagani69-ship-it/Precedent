# Checkpoint 2

Moderator swap tests, pooled checks, bounded web verification, fresh-evidence
resets, stopping rules, scored values/situational questions, answer/resume,
full verdicts, and preference persistence are implemented. The question card
accepts only the council owner's answer. Pooled checks distinguish observed
counts from smoothed estimates; web belief estimates are labeled as model
interpretations and require a matching source passage.

24 tests pass. An offline council with 40 explicit test records generated a
three-choice values question, accepted an answer, resumed through the real
worker/storage path, produced a verdict, and saved the preference. Another
exercise verified shared data checks and next-round stance movement. Blocked
pages and unsupported verification quotes produced no web evidence.

These are deterministic offline checks, not proof of a live service-backed
happy path. The live source limitation recorded in Checkpoint 1 remains.
The completion request authorizes proceeding to Phase 3.
